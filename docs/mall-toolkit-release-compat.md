# 工具包订单无需前端发版的跳转兼容

2026-10-27：已部署 `mall_orders_list` 后端兼容。

旧客户端按请求来源决定展示类型：商城响应经 `formatOrder` 转成 `_type: mall`，工具包响应经 `formatToolkitOrder` 转成 `_type: toolkit`。旧版 `onDetail` 仅在 mall 分支进入订单详情，toolkit 分支进入商品详情。

商城查询现在同时匹配原有 `type: mall` 和 `category: mall/goods/toolkit`，用户、删除状态和其他查询条件仍共同生效；按订单号直接查询的路径不变。数据库中的工具包分类、权限和金额未修改。

旧客户端先合并商城响应，再合并工具包响应，按订单号去重，因此同时返回的工具包订单保留商城展示分支，点击进入订单详情。列表标题会显示商城订单。

线上函数原版本含订单类型筛选、虚拟状态文案和批量图片转换，本次全部保留。部署前完整函数包保存在工作区 `tmp/mall-toolkit-compat-backup/mall_orders_list.original.zip`，可用于回滚。

验证：`node specs/mall-toolkit-release-compat.test.js` 驱动真实云函数和页面加载流程，并使用修复前的跳转处理函数，确认工具包只显示一次、跳转携带订单号、其他用户及已删除订单被排除、课程查询及数据库分类保留。页面跳转和虚拟发货两组既有回归也通过。

分页兼容：商城响应除混合列表当前页外，还补齐独立工具包查询同一页的数据，按订单号去重。这避免旧工具包落在混合列表分页之外时仍走错误分支；回归测试覆盖了 25 笔更新的商城订单挤出旧工具包的情况。该商城兼容响应最多额外包含一页工具包，统计总数仍是匹配订单的实际总数。独立工具包查询及按订单号查询不变。

此方案依赖旧客户端同时获取商城/工具包列表且按商城优先去重；前端长期修复仍应随下一版发布。没有宣称已进行用户手机上的正式版 UI 验收。
