# 动态收集表需求文档

## Introduction

本功能允许管理员为住宅、疗愈服务、辅助办公和运动健身四种空间配置动态收集表。小程序按已发布版本渲染一页一题流程，用户无需登录即可提交，后台可按提交时版本查看和导出答案。

## Requirements

### Requirement 1 - 模板草稿与发布

**User Story:** 作为管理员，我希望编辑草稿不会影响线上表单，并能在确认后发布新版本。

#### Acceptance Criteria

1. 当管理员初始化功能时，系统应创建四个空白草稿且不创建已发布版本。
2. 当管理员保存草稿时，系统应递增草稿修订号且不得修改当前发布版本。
3. 当管理员携带过期修订号保存或发布时，系统应返回 `CONFLICT` 且不得覆盖新数据。
4. 当管理员发布有效草稿时，系统应生成不可变版本并切换该空间类型的发布指针。
5. 当草稿不完整时，系统应拒绝发布并返回可定位的问题列表。

### Requirement 2 - 表单设计器

**User Story:** 作为管理员，我希望通过可视化界面配置模块、题目、选项、校验和条件显示。

#### Acceptance Criteria

1. 当管理员编辑表单时，系统应支持 `single`、`multiple`、`shortText`、`longText`、`number`、`location`、`upload`、`ranking`、`table` 九种题型。
2. 当管理员调整模块、题目或选项顺序时，系统应保留稳定 ID 并重新生成展示编号。
3. 当管理员配置条件题时，系统应仅允许引用当前题之前的单选或多选题。
4. 当管理员配置表格题时，系统应支持 1–10 个短文本、长文本、数字、单选或多选列；支持列必填、选项、字数/数值/选择数量限制、单位、输入提示及最少/最多行数；最多行数留空时按 100 行处理。
5. 当填写者作答表格题时，系统应以相同字段动态新增或删除多行，并按行校验、保存、提交和展示答案。
6. 当管理员预览草稿时，系统应以小程序黑白一页一题样式呈现当前配置。

### Requirement 3 - 小程序动态读取

**User Story:** 作为填写者，我希望始终能打开表单，并在网络异常时继续使用可用版本。

#### Acceptance Criteria

1. 当存在远程已发布版本时，小程序应优先使用并缓存该版本。
2. 当远程未发布、不可用或结构非法时，小程序应依次使用缓存版本和内置模板。
3. 当旧版草稿存在且后台已发布新版本时，小程序应允许继续旧版或重新使用最新版。
4. 当用户继续旧版时，系统应保留对应模板快照并允许按该历史版本提交。

### Requirement 4 - 上传与提交

**User Story:** 作为填写者，我希望上传资料并可靠提交，失败后可以重试且不会产生重复记录。

#### Acceptance Criteria

1. 当用户确认提交时，小程序应先持久化临时文件，再调用提交云函数。
2. 当文件上传失败时，系统应保留草稿并阻止创建提交记录。
3. 当提交请求重复到达时，系统应依据 OPENID 与 `requestId` 返回同一记录。
4. 当服务端接收答案时，系统应按提交版本重新计算可见题并验证答案。
5. 当提交成功时，系统应清除活动草稿索引但保留确认页答案。

### Requirement 5 - 提交记录管理

**User Story:** 作为管理员，我希望按历史版本查看、筛选和导出动态表单记录。

#### Acceptance Criteria

1. 当管理员打开记录详情时，系统应使用提交时的不可变模板版本渲染问题。
2. 当管理员筛选记录时，系统应支持空间类型、版本、日期和关键词。
3. 当管理员导出时，系统应要求选择空间类型与版本并生成 UTF-8 BOM CSV。
4. 当筛选结果超过 10,000 条时，系统应阻止导出并提示缩小范围。
5. 旧 `lighting_collections` 记录应保持原状且不得混入新版记录。

## Design Specification

- Purpose：提供高密度、低干扰的管理员表单编排工具，并准确预览小程序体验。
- Aesthetic Direction：后台采用 Industrial/utilitarian；小程序预览采用 Brutally minimal。
- Palette：后台 `#1E3A5F`、`#0F172A`、`#F8FAFC`、`#E2E8F0`；小程序 `#FFFFFF`、`#0B0B0B`、`#777777`、`#E8E8E8`。
- Typography：后台 `DM Sans`、`Source Sans Pro`；小程序 `PingFang SC`、`Microsoft YaHei`。
- Layout：左侧模块、中间题目、右侧属性的非对称三栏工作台，手机预览使用右侧抽屉。
