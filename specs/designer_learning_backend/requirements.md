# 需求文档：设计师端学习页三个课程板块后端联调

## 1. 简介

设计师端新版学习页 `pages/v2/designer-learning/index` 已完成视觉界面，页面“课程内容”区域包含三个入口：

1. 课程介绍
2. 课程目录
3. 学习记录

本期只完成上述三个板块的后端云函数能力、小程序端数据接入，以及与现有后台管理系统的联调。课程主卡片、推荐卖点、购买流程、播放器重构等内容不纳入本期。

后台管理系统已经具备课程基础信息维护、章节课时管理和学习进度管理页面。本期应复用现有 `courses` 与 `course_progress` 数据，使后台保存的课程介绍和目录能够在设计师端生效，同时让小程序产生的学习记录能够在后台“学习进度管理”中正确查询。

所有开发和联调均连接项目当前生产 CloudBase 环境，不创建或使用测试环境；正式版旧 UI 与新版渠道分流规则保持不变。

## 2. 本期目标

- “课程介绍”读取后台课程管理中维护的真实课程资料。
- “课程目录”读取后台章节管理中维护的真实章节和课时结构。
- “学习记录”读取当前设计师本人的真实学习进度和最近学习课时。
- 后台编辑并发布课程后，小程序能够读取最新已发布内容。
- 小程序更新学习进度后，后台学习进度管理能够读取同一份记录。
- 不向课程介绍或目录接口泄露视频地址、附件地址、网盘密码等受保护资源。

## 3. 本期范围

### 3.1 包含范围

- 设计师身份与当前用户数据隔离。
- 课程介绍查询云函数能力。
- 课程目录查询云函数能力。
- 当前用户学习记录查询云函数能力。
- 复用现有 `course_progress_update` 写入学习进度，并修复必要的兼容问题。
- 复用或修复后台：
  - `课程管理`中的课程介绍编辑；
  - `课程管理`中的章节和课时编辑；
  - `学习进度管理`中的课程筛选、列表与详情读取。
- 设计师端三个入口与真实后端数据联调。
- 本地自动化测试及微信开发者工具联调检查。

### 3.2 不包含范围

- 不开发学习页课程主卡片、讲师卡片或三项课程卖点的动态配置。
- 不开发推荐课程算法、多课程推荐流或课程搜索。
- 不重构课程购买、白名单、支付或订单逻辑。
- 不重构视频播放器、附件下载器或视频清晰度功能。
- 不新增学习时长排行榜、学习证书、考试统计或运营报表。
- 不改变学习页现有黑白 UI 风格、文案层级和四项底部导航。
- 不修改正式版旧 UI 的页面和路由。
- 不部署或连接测试 CloudBase 环境。

## 4. 现有数据与后台能力

| 能力 | 现有数据/页面 | 本期联调目标 |
| --- | --- | --- |
| 课程介绍 | `courses`；后台 `CourseList` 基础信息与详情图片 | 后台保存、发布后，设计师端课程介绍可读取 |
| 课程目录 | `courses.chapters`；后台 `ChapterManager` | 后台章节及课时排序、增删改后，设计师端目录一致 |
| 学习记录 | `course_progress`；`course_progress_update` | 当前设计师可读本人记录，后台可查看同一记录 |
| 后台进度管理 | `LearningProgress`；`admin_course_progress_list` | 课程筛选、列表、详情字段与生产数据一致 |

## 5. 需求

### 需求 1：身份识别与数据隔离

**用户故事：** 作为设计师，我希望只能读取自己的学习记录，同时可以查看已发布课程的公开介绍和目录。

#### 验收标准

1. **When** 学习记录接口收到请求，**the system shall** 仅使用云函数运行上下文中的 `OPENID` 识别当前用户，不接受客户端传入的 `openid` 作为身份依据。
2. **If** 学习记录请求不存在有效 `OPENID`，**then the system shall** 返回 `success: false` 和错误码 `UNAUTHENTICATED`。
3. **When** 查询当前用户资料，**the system shall** 兼容 `users._openid` 与 `users.openid` 两种历史字段。
4. **If** 当前用户不是设计师或管理员角色，**then the system shall** 返回 `NOT_DESIGNER`，不得返回学习记录。
5. **While** 查询学习记录，**the system shall** 始终以当前 `OPENID` 限定 `course_progress` 数据范围。
6. **When** 后台管理员查询学习进度，**the system shall** 继续使用后台既有管理员鉴权，不复用小程序设计师身份校验。

### 需求 2：课程介绍板块

**用户故事：** 作为设计师，我希望点击“课程介绍”后看到后台维护并已发布的真实课程内容。

#### 验收标准

1. **When** 小程序请求某门课程的介绍，**the system shall** 按课程文档 `_id` 或业务 `courseId` 查询 `courses` 集合。
2. **When** 课程处于 `published` 且未被软删除，**the system shall** 返回公开课程介绍数据。
3. **If** 课程为草稿、已下架或已删除，**then the system shall** 返回 `COURSE_NOT_AVAILABLE`，不得返回该课程内容。
4. **When** 返回课程介绍，**the system shall** 至少包含课程 ID、名称、副标题、文字简介、讲师名称、讲师头像、封面图、详情图片、适用人群、课程亮点和收益列表中已配置的公开字段。
5. **When** 封面、讲师头像或详情图片使用 `cloud://` 文件 ID，**the system shall** 批量换取临时访问地址后返回；普通 HTTPS 地址保持不变。
6. **While** 返回课程介绍，**the system shall not** 返回 `videoUrl`、`videoUrls`、`fileUrl`、网盘链接、网盘提取码、备用联系方式和后台内部字段。
7. **If** 某个可选介绍字段未配置，**then the system shall** 返回安全默认值或省略可选字段，不得导致页面白屏。

### 需求 3：课程介绍与后台课程管理联调

**用户故事：** 作为后台管理员，我希望修改并发布课程介绍后，设计师端能显示最新内容。

#### 验收标准

1. **When** 管理员在后台课程管理中保存课程名称、副标题、简介、讲师、封面、详情图片、适用人群、亮点或收益列表，**the system shall** 将数据写入小程序课程介绍接口读取的同一份 `courses` 文档。
2. **When** 管理员发布课程，**the system shall** 使该课程介绍能够被小程序公开接口读取。
3. **When** 管理员将课程下架，**the system shall** 使小程序课程介绍接口立即停止返回该课程内容。
4. **When** 管理员调整详情图片顺序并保存，**the system shall** 保持小程序端返回顺序与后台一致。
5. **If** 后台历史数据使用 `cover`、`coverUrl`、`images` 或 `detailImage` 等兼容字段，**then the system shall** 在不破坏原数据的前提下归一化输出。

### 需求 4：课程目录板块

**用户故事：** 作为设计师，我希望点击“课程目录”后按后台设定的章节和课时顺序浏览课程结构。

#### 验收标准

1. **When** 小程序请求某门课程的目录，**the system shall** 仅对已发布且未删除的课程返回 `chapters` 结构。
2. **When** 返回课程目录，**the system shall** 保持后台配置的章节顺序和章节内课时顺序。
3. **When** 返回章节，**the system shall** 至少包含章节标题、章节序号和课时数量。
4. **When** 返回课时，**the system shall** 至少包含课时 ID、标题、类型、显示时长、格式、题目数量、及格分和可公开状态中适用的字段。
5. **While** 返回课程目录，**the system shall not** 返回任何视频地址、多清晰度视频地址、文件下载地址或未发布资源凭证。
6. **If** 课程没有章节或章节没有课时，**then the system shall** 返回空数组，供小程序展示空状态，不将其视为接口失败。
7. **If** 目录中存在缺少 ID、标题或类型的无效课时，**then the system shall** 过滤或安全归一化该课时，并记录服务端告警，不得令整个目录请求失败。

### 需求 5：课程目录与后台章节管理联调

**用户故事：** 作为后台管理员，我希望章节和课时的增删改、排序和发布结果能准确反映到设计师端。

#### 验收标准

1. **When** 管理员通过后台 `ChapterManager` 新增、编辑、删除或排序章节与课时并保存，**the system shall** 更新小程序目录接口读取的 `courses.chapters`。
2. **When** 后台保存视频、文件或作业课时，**the system shall** 保持唯一且稳定的课时 ID，避免用户历史进度因普通编辑而丢失关联。
3. **When** 管理员只修改课时标题、时长或顺序，**the system shall** 保留原课时 ID。
4. **When** 管理员删除已有学习记录关联的课时，**the system shall** 允许课程保存；小程序学习记录接口应忽略无法匹配的悬空记录，并保留其他有效历史。
5. **When** 后台保存章节数据，**the system shall** 校验章节数组、课时类型、课时 ID 唯一性及必要字段，非法数据不得进入已发布课程。

### 需求 6：学习记录板块

**用户故事：** 作为设计师，我希望点击“学习记录”后看到自己最近学习的课时、完成情况和观看进度。

#### 验收标准

1. **When** 小程序请求当前课程的学习记录，**the system shall** 从 `course_progress` 查询当前 `OPENID` 与当前课程对应的记录。
2. **When** 存在学习记录，**the system shall** 返回总体进度、总课时数、已完成课时数、最后学习课时、最后学习时间和最近课时列表。
3. **When** 生成最近课时列表，**the system shall** 根据 `lessonProgress.*.lastWatchedAt` 降序排序，第一版最多返回 20 条。
4. **When** 返回单条课时记录，**the system shall** 包含课时 ID、课时标题、章节标题、观看进度、完成状态和最后学习时间。
5. **When** 进度字段存在历史格式差异，**the system shall** 将百分比限制在 `0-100`，计数限制为非负整数，并使用当前课程目录补齐课时和章节标题。
6. **If** 用户没有该课程的学习记录，**then the system shall** 返回总体进度为 0 和空记录数组，不将其视为错误。
7. **If** 历史记录关联的课时已从课程目录删除，**then the system shall** 不把该悬空记录返回为可点击课时，并保留其他有效记录。
8. **While** 返回学习记录，**the system shall not** 返回视频 URL、附件 URL 或其他用户信息。

### 需求 7：学习记录写入链路兼容

**用户故事：** 作为设计师，我希望观看课程后的进度能被可靠保存，并在再次进入学习记录时看到最新状态。

#### 验收标准

1. **When** 现有播放器调用 `course_progress_update`，**the system shall** 按当前 `OPENID`、课程 ID 和课时 ID 更新或创建唯一进度记录。
2. **When** 同一课时重复上报进度，**the system shall** 幂等更新该课时的进度和最后观看时间，不产生重复课时记录。
3. **When** 课时进度达到完成阈值，**the system shall** 将其标记为完成，并同步更新整体完成数量和总体进度。
4. **When** 新进度写入成功，**the system shall** 使小程序学习记录接口和后台学习进度管理读取到一致结果。
5. **If** 上报课程 ID 或课时 ID 不存在于当前已发布课程，**then the system shall** 拒绝写入并返回稳定错误码，避免产生新的悬空记录。

### 需求 8：后台学习进度管理联调

**用户故事：** 作为后台管理员，我希望在“学习进度管理”中查询设计师的真实学习记录并查看课时明细。

#### 验收标准

1. **When** 管理员打开后台学习进度管理，**the system shall** 通过 `admin_course_progress_list` 返回真实 `course_progress` 数据和正确总数。
2. **When** 后台加载课程筛选项，**the system shall** 正确解析课程列表接口的实际响应结构，并显示可筛选的已发布课程。
3. **When** 管理员按课程或关键词筛选，**the system shall** 返回匹配的进度记录，并保持分页总数准确。
4. **When** 后台显示一条学习进度，**the system shall** 返回用户昵称、头像、课程名称、课程封面、总体进度、总课时数、完成数量、最后学习课时和更新时间。
5. **When** 管理员查看进度详情，**the system shall** 返回有效课时的章节标题、课时标题、观看进度、完成状态和最后观看时间。
6. **If** 用户或课程历史文档缺失，**then the system shall** 使用明确占位文本展示该记录，不令整个后台列表失败。
7. **While** 后台管理员查看学习记录，**the system shall not** 返回视频地址、附件下载地址、网盘密码或不必要的用户敏感信息。

### 需求 9：设计师端三个入口接入

**用户故事：** 作为设计师，我希望三个入口都进入对应真实功能，而不是静态占位或错误复用同一页面。

#### 验收标准

1. **When** 用户点击“课程介绍”，**the system shall** 携带当前课程 ID 打开使用真实介绍数据的页面或页面状态。
2. **When** 用户点击“课程目录”，**the system shall** 携带当前课程 ID 打开使用真实目录数据的页面或页面状态。
3. **When** 用户点击“学习记录”，**the system shall** 打开当前用户、当前课程的学习记录视图，不再将该入口等同于普通课程目录。
4. **While** 三个板块加载数据，**the system shall** 提供加载中、空数据、失败重试和正常内容四类状态。
5. **If** 云函数返回字段缺失或请求失败，**then the system shall** 展示中文错误提示且不白屏、不产生未捕获异常。
6. **While** 接入真实后端，**the system shall** 保持当前学习页的中文文案、黑白新版 UI 和底部导航不变。

### 需求 10：接口安全、错误处理与可观测性

**用户故事：** 作为维护人员，我希望接口失败可定位、内容安全且不会因为重复请求产生副作用。

#### 验收标准

1. **When** 接口成功，**the system shall** 使用统一结构 `{ success: true, code: 'OK', data }`。
2. **When** 参数不合法，**the system shall** 返回 `INVALID_PARAMS`；当课程不存在时返回 `COURSE_NOT_FOUND`；当课程不可用时返回 `COURSE_NOT_AVAILABLE`。
3. **When** 发生未知异常，**the system shall** 返回 `INTERNAL_ERROR` 和不暴露数据库内部细节的中文错误信息。
4. **When** 云函数处理请求，**the system shall** 记录动作、匿名化用户标识、课程 ID、耗时和结果码，不记录视频地址、密码或完整敏感信息。
5. **When** 客户端重复请求课程介绍、课程目录或学习记录，**the system shall** 保持读取操作幂等。
6. **While** 转换云存储图片地址，**the system shall** 使用批量临时链接转换，避免逐图片串行调用。

### 需求 11：兼容性与生产环境约束

**用户故事：** 作为产品负责人，我希望本次联调不影响线上旧版用户，也不误用测试环境。

#### 验收标准

1. **While** 开发三个学习板块，**the system shall** 保持正式版旧 UI 的页面、Tab、路由分流和既有课程链路不变。
2. **While** 开发版和体验版使用新版学习页，**the system shall** 继续遵守现有 V2 渠道门禁，不扩大新版 UI 到正式版线上用户。
3. **When** 初始化 CloudBase 或部署云函数，**the system shall** 使用项目现有生产环境配置，不硬编码新的环境 ID，不创建、不读取、不部署到测试环境。
4. **While** 联调现有集合，**the system shall** 兼容历史课程和学习进度字段，不执行破坏性生产数据迁移。
5. **When** 功能开发完成，**the system shall** 先通过本地自动化测试、后台构建检查和微信开发者工具联调；生产部署必须等待用户明确授权。

## 7. 测试要求

- 课程介绍：已发布、草稿、下架、已删除、历史图片字段、云文件临时地址、敏感字段过滤。
- 课程目录：空目录、多个章节、排序、视频/文件/作业课时、无效课时、资源地址过滤。
- 学习记录：未登录、非设计师、无记录、有记录、重复上报、完成阈值、悬空课时、用户数据隔离。
- 后台联调：课程介绍保存与发布、章节保存与排序、课程筛选响应、进度列表分页、进度详情。
- 回归：现有课程详情、课程视频、进度更新、旧版 UI 和 V2 渠道门禁测试继续通过。
- 编码：源码、接口响应和日志中的中文统一使用 UTF-8，不出现乱码。
